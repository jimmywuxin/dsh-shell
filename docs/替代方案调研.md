# 替代方案调研（2026-10-06）

「把 localhost 上的 dsh web 变成 macOS app」有哪些现成做法，以及为什么本项目不用。

## 结论：不换

三条理由见文末。**先记事实，别重复调研。**

## 方案对比

| 方案 | 独立 profile | 体积 | 处理「服务没起」 | 结论 |
|---|---|---|---|---|
| **本项目**：Edge `--app` + shell launcher | ✅ `~/.dsh/edge-profile` | 8KB shell | ✅ launchd kickstart + HTTP 就绪轮询 | 采用 |
| Edge 内置 PWA（`菜单 → Apps → Install This Site as An App`） | ❌ **共享日常 profile** | ✅ | ❌ | 唯一真正省事的路，但违背需求 |
| `nativefier` / Fluid / Unite / Web2Desk | ✅ | ❌ 150MB（Electron） | ❌ | 体积爆炸 |
| Tauri | ✅ | ✅ ~10MB | ❌ | 要Rust 工具链 |
| `github/davidondrej/skills` 的 `persistent-localhost.sh` | — | — | ✅ 见下 | 管的是服务生命周期，不是开窗 |

## Edge 内置 PWA：最省事但共享 profile

`Edge 菜单 → Apps → Install This Site as An App` → app 落在
`~/Applications/Edge Apps.localized/`，自带无地址栏窗口，进 Dock 与 Spotlight。

**致命限制**（openpwa.net/reference/installation/desktop-install 明确写）：
> Cookies and storage are **shared with the installing browser profile** on Chrome
> and Edge, so sign-in carries over.

共享日常 Edge profile —— 这正是本项目 2026-10-05 拆独立 profile 的核心原因
（commit 840dbeb）。**官方方案不能替代。**

管理面在 `edge://apps`。

## persistent-localhost.sh：服务侧写得比我们清楚

`github/davidondrej/skills` → `skills/ops-and-setup/persistent-localhost/`
（脚本在 `scripts/persistent-localhost.sh`）

用法与它比我们强的地方：

```bash
scripts/persistent-localhost.sh start --name myproj --port 5111 --cmd "./bin/serve"
# ↑ 返回时端口已 listening（不用自己轮询）；失败则打印最后 20 行日志
scripts/persistent-localhost.sh status|restart|logs|stop myproj
```

- **就绪即返回**（我们现在是自己在 `wait_ready` 里轮询 HTTP 状态码）
- `KeepAlive only on crash. A clean exit stays down.` —— 干净退出不重启，
  避免「手动停了又被拉起来」。**这条我们踩过**（`launchd_managed` 判托管那段）
- 端口被占的归属处理：自己的实例换掉，别人的留着
- 日志 `~/Library/Logs/persistent-localhost/.log`、
  状态 `~/Library/Application Support/.../.state`、plist `~/Library/LaunchAgents/`
- 它也明确禁止 `nohup, &, disown, setsid, run_in_background` 启服务

**但它解决的是服务生命周期，不解决开窗。** 我们的 launchd 集成
（`launchd_managed` 判托管、HTTP 判就绪、失效锁 `kill -0` 探活）已做到同等粒度。
**在其他机器上复刻时，可以参考它的思路与目录布局。**

## 什么时候该重新评估

如果 **dsh 官方出了 macOS 客户端**，直接换官方；在此之前 Edge PWA 那条路
（`edge://apps`）是次优备选 —— 只在「不介意 cookie 混进日常 profile」时才成立。

## 本项目的独有价值（也就是为什么自己写）

1. **服务未起时的拉起链路**：kickstart → bootstrap plist → nohup 三级兜底
2. **独立 profile + 翻译气泡抑制 + 失效锁清理**
3. **就绪判据看 HTTP 状态码**（半启动态会 bind 3080 但返 404，只看端口会误报）
4. 三个脚本共享同一套判据（`src/dsh-lib.sh`）
